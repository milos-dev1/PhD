Chapter 1
GA-Based DNN Classifier Architecture
Optimization
This standalone chapter presents the genetic algorithm (GA) method used to
discover deep neural network (DNN) classifier architectures for multi-sensor
vibration diagnosis. The classifier input is the fused feature vector Zf usion ∈
R448 . The chapter is organized in three sections: (1) how candidate architec-

tures are represented and what search space is used; (2) how the GA searches
that space with selection, crossover, mutation, and elitism; (3) how the same
procedure is applied one machine/sensor configuration at a time to obtain C∗ .
Every formula is accompanied by the reason it was chosen. This document
does not modify the main doctoral thesis files.

1.1

DNN Architecture Representation and Search Space

1.1.1 Motivation: Why Architecture Must Be Searched
Manual design of DNN classifiers for fault diagnosis is brittle. A network that works for
one sensor layout may fail for another because the decision boundary induced by Zf usion
changes with the sensing configuration. Exhaustive trial of depths, widths, activations,
and dropout rates is combinatorial: even a modest discrete grid already contains enormous
numbers of candidates when variable depth is allowed, and each candidate requires a full

1. Collect multi-sensor data for the new configuration.

2. Build Zf usion features and labels; split train/validation/test.

∗

1.3.3 Three Deployment Policies Compared
1.

Universal fixed DNN: one hand-designed architecture for all configurations.

2.

Transfer: run GA on A, reuse C∗A on B without re-search.

3.

Re-search (this chapter): run GA independently on each configuration.

Why present all three?

Policy 3 is the methodological recommendation. Policies 12

are necessary experimental baselines: if transfer already matches re-search, the plant can
skip compute. The chapter does not assume re-search always wins by a large margin; it
provides claim (1.15) and the protocol to test it.

1.3.5 What This Method Deliberately Does Not Do
 Evolve learning rates or batch sizes (would confound architecture eects).
 Return a Pareto front of accuracy vs. size (hard cap + single macro-F1 objective).
 Use one-shot weight-sharing NAS (prefers full training per candidate).
 Co-evolve weights with topology (backprop trains weights for each decoded MLP).

1.3.6 Common Implementation Pitfalls
 Using test macro-F1 inside the GA (contaminates selection).
 Forgetting wrap indexing in crossover (illegal children when depths dier).
 Evolving learning rate with architecture (confounds structure claims).
 Random splits of temporally adjacent samples (inflated fitness).
 No elitism (best architectures disappear under noise).

1.3.7 Discussion
The fitness landscape over S is rugged: one width or dropout change can move macro-F1
by several points. Tournament selection, layer-block crossover, one-gene mutation, and
elitism are chosen together so the search can climb local hills without abandoning an entire
depth niche too early. Section 1.1 defined what is searchable; Section 1.2 defined how to
search; Section 1.3 defined how to deploy the search per configuration. That three-way
split is the structure of the method.
